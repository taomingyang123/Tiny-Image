# 06｜测试矩阵与上线验收

## 1. 测试资产

使用可再分发或自行生成的图片测试集（仓库可放小型 fixtures，大文件仅保留生成脚本）。建议生成：1x1 JPEG、普通高分辨率 JPEG、含 EXIF orientation JPEG、透明 PNG、调色板 PNG、复杂文本截图 PNG、已充分优化 PNG、WebP 有损与无损、动画 WebP、APNG、错误文件头、损坏文件、同名文件、超尺寸/超体积模拟输入、包含危险文件名 `../photo.png` 的模拟文件。

实际像素一致性使用图像解码后逐像素比较；PNG 直接优化通道必须 RGBA 等值，必要时对颜色管理及 16bit 输入另做单独策略和支持说明。

## 3. 浏览器矩阵

- 桌面：Chrome 当前稳定版、Edge 当前稳定版、Firefox 当前稳定版、Safari macOS 当前稳定版。
- 移动：iOS Safari 近期稳定版、Android Chrome 近期稳定版。
- 对不支持 Worker createImageBitmap/OffscreenCanvas 的浏览器：要么有经过测试的 fallback、要么友好降级（不得白屏）。
- Mac M4 本地测试 + 一款资源受限的移动设备尤为重要；模拟器不能完全代替真机内存测试。

## 4. 安全与隐私验证

- DevTools 拦截/检查全部 fetch、XHR、beacon、worker fetch。允许本站 JS/CSS/WASM 页面资源加载，不允许发送任意图片字节或用户文件名至第三方。
- 文件名包含 HTML 标记、控制字符、`../`、Unicode 混合字符，不造成 XSS 或 ZIP 路径穿越。
- 构造带恶意内容的非支持格式 / SVG，拒绝压缩与浏览器可执行渲染。
- 审核 CSP 中 `script-src`、`worker-src`、`img-src`、`connect-src` 与真实 WASM 运行需求；修复所有 CSP console error。
- 跟踪 `blob:` URL 的创建/销毁，没有明显资源累积；取消后重复 20 次运行不造成任务卡死。

## 5. 质量与性能验收

- 首屏无需加载 WASM；静态 HTML 可被抓取、页面布局稳定。
- 压缩时主 UI 能响应点击、滚动和“取消”操作；取消有明确反馈，不能冻结界面直至编码结束。
- 首版目标：桌面 Lighthouse SEO / Accessibility / Best Practices ≥ 90，Performance 争取 ≥ 90（均为目标，不是承诺；测试无图片上传空闲首页）；移动至少完成体验和实际性能报告。
- 真实图片的压缩率、耗时记录至少 12 个不同样本，不预设每张都缩小，不用与不相同质量指标下的竞争工具结果做夸张对比。
- Nuxt CI typecheck、lint、unit、generate 全部通过；至少 1 组 Playwright 真浏览器压缩任务集通过。
- 验证官方 Pages 域名和自定义域名的 200、静态资源 200、语言路由 200、无奇怪 404 SPA fallback。
