# 04｜界面设计、国际化和 SEO 方案

## 1. 视觉与布局

产品名：Tiny Image；视觉延续 tinystool 家族的简洁工具感，但项目设计系统独立维护。建议中性色为背景、蓝色为主要交互色、绿色仅作为成功状态、红色用于错误，尽量使用系统字体；暗色模式可作为增强项。遵循 WCAG AA 的对比和键盘访问基本要求。

### PC 页面层级

1. Topbar：Tiny Image 标志、语言切换、隐私说明、返回 Tiny's Tool 链接。
2. Hero：H1“在线图片压缩——免费、本地处理、无需上传”；一句价值说明。
3. 上传区域：大拖拽面板、文件选择按钮、格式说明、容量限制、隐私图标。
4. 压缩设置：输出格式 `保持原格式/JPEG/WebP`；有损时质量滑杆；最长边可选；支持格式提示。
5. 任务结果：文件表格（缩略图、名称、原始体积、结果体积、节省、状态、下载/重试/移除）。
6. 预览抽屉：实际编码前后图像对比；大图只加载正在查看的项。
7. 下载操作：全部成功图片 ZIP，或逐张下载。没有成功项时禁用。
8. 下方静态内容：“图片如何在浏览器压缩”“格式建议”“FAQ”“隐私声明”“工具局限”。
9. Footer：版权/关于/隐私/主站返回链接。

### 移动端

- 上传区、设置区纵向堆叠；任务卡片代替宽表格；底部操作按钮可悬浮，但要考虑安全区域和键盘。
- 质量滑块有可直接输入数值的替代方式；点击热区至少 44px；图片预览区域适配窄屏。
- 大图出现内存保护提示；不假设手机拥有 OffscreenCanvas 或无限 RAM。

## 2. 基础交互要求

- 拖拽 `dragover/drop` 阻止浏览器导航；上传 input 允许多选；文件校验是确定性流程。
- 页面预览不强制加载全尺寸图片；右侧示意压缩率只显示实际结果，不展示“预计减少 90%”。
- 按钮禁用有原因文字；进度区域使用 `aria-live` 通报状态；文件清单有清晰的状态说明。
- 不保留上传文件跨刷新；刷新后任务和临时文件消失是正常行为。
- 重新选择输出格式只影响尚未启动的新任务；已完成的结果应标记为需要重新压缩或保留原任务配置，避免误导。

## 3. URL/SEO 结构

| URL | 语言 | 说明 |
|---|---|---|
| `/` | zh-CN | 唯一默认中文首页 |
| `/en/` | en | 英文同等质量的产品页面 |
| `/ja/` | ja | 日文同等质量的产品页面 |
| `/privacy/` | zh-CN | 详细隐私政策 |
| `/en/privacy/` | en | 英文隐私 |
| `/ja/privacy/` | ja | 日文隐私 |

不必为每一种格式人为创建内容稀薄的新 SEO 页面。后续只有在真实功能与有用教程成形后才扩展 `/png-compressor/` 或 `/webp-converter/` 等页面。

- 每个语言路径拥有独立标题、描述、H1、FAQ、canonical；用 `hreflang` 双向关联 3 个语言版本，设置 `x-default`；所有 canonical 使用完整生产绝对 URL `https://image.tinystool.org/...`。
- `nuxt generate` 预渲染 6 个静态页面，确保“源代码查看”中可见正文与主要 HTML，而非仅 JS hydration。
- `sitemap.xml` 只列入完整可用且允许收录的页面，不包含预览地址。
- `robots.txt`: 允许正常抓取，标注 sitemap。不得屏蔽 `/_nuxt/` JS/样式，避免渲染障碍。
- 页面图标、OG 图、manifest 可以静态托管；首屏不启动编解码器和文件 API。
- 基础结构化数据可考虑 `WebApplication` + 真实常见问答 FAQ，但符合 Google 当前结构化结果政策；**结构化标记不等于保证富摘要**。
- 不做自动生成空洞文章、模板化多语言关键词堆砌；首页讲清楚限制：不支持动画、AVIF 延后、压缩可能变大。

## 4. 建议 SEO 标题（需实际审校）

- 中文 title：`在线图片压缩工具 - JPG、PNG、WebP 本地压缩 | Tiny Image`
- 中文 description：`免费在线压缩 JPG、PNG、WebP 图片。浏览器本地处理，无需上传图片，支持批量压缩、图片尺寸调整与 ZIP 下载。`
- 英文 title：`Free Online Image Compressor – JPG, PNG & WebP | Tiny Image`
- 日文 title：`無料オンライン画像圧縮 – JPG・PNG・WebP | Tiny Image`

注意 v1 无损仅适用于 PNG 的特定处理路径；不可让文案给人所有压缩都无损的印象。

## 5. FAQ 题目

- 图片会上传到服务器吗？（不会，处理时只从本站加载程序资源。）
- 压缩会损失图片质量吗？（JPEG/WebP 质量调整是有损；PNG 无损优化不同。）
- 为什么 PNG 压缩后变化不大？（编码状态、照片 vs 截图、调色板与元数据。）
- 为什么压缩后图片变大？（格式/质量/原始编码已高效。）
- 为什么大图或 iPhone 上处理失败？（设备内存、浏览器能力或大小限制。）
- JPEG 和 WebP 有什么区别？（透明支持与兼容、大小不保证。）
- 支持 GIF/AVIF/HEIC 吗？（首版不支持，未来视工程验证而定。）

## 6. 隐私与可观测性

隐私页必须写明：文件不传服务器；选图后处理发生在访问者的浏览器；不会存储图片/文件名；访问站点本身仍会产生常规的静态资源请求和托管服务访问日志；可选的匿名访问统计只能统计站点访问信息，不能读取或传送图片内容、文件名、像素、数据 URL。若后续接入分析脚本，则必须如实更新政策和 CSP，不可绝对表述为“完全零数据传输”。

特别说明：**导出的图片可能含有或丢失 EXIF/ICC 等元数据，第一版不承诺彻底清除 GPS/隐私元信息。** 需要清理时必须另做专门可验证功能。

SEO 建议独立添加 Google Search Console 子域名属性（或复用已验证的域名属性查看），单独观察索引状态、Performance、Core Web Vitals；多语言索引遵循质量优先原则。
