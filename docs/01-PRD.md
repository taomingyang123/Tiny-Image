# 01｜产品需求说明 PRD

> 2026-10-14 实现修订（T04-07～T04-10）：输出模式包含 `keep/jpeg/png/webp`；当前 UI 提供原格式/JPEG/PNG，WebP 保留输入原格式压缩。原格式 PNG 不量化；显式转 PNG 且质量低于 100 才量化。缩放改变像素。原格式 JPEG/WebP 为有损重编码。实际验收与遗留项见 [审查报告](verification/2026-10-14-feature-audit.md)，本文件的初版目标不作为测试通过证据。

## 1. 目标与定位

产品：Tiny Image；正式地址 `https://image.tinystool.org/`。核心价值：无需注册、无需上传、纯浏览器本地完成图片压缩。面向个人站长、前端开发者、内容运营、普通用户。站点与 tinystool.org 主站仓库/部署解耦。

**成功标准**：首次访问用户可在不读教程的前提下上传 1 张 JPEG/PNG/WebP，设置参数、完成任务、查看前后体积和下载；批量上传多个文件、逐文件状态明确、可打包下载。移动端可完成同样流程。

## 2. P0 上线范围

- 拖拽区域 + 文件选择 + 支持一次选择多个；输入 accept 仅提示，实际依据文件签名判断。
- JPEG→JPEG（MozJPEG）、PNG→PNG 无损（OxiPNG）、WebP→WebP；JPEG/PNG/WebP→JPEG/WebP 的格式转换（按 codec 的支持矩阵与浏览器解码能力提供）。
- 每张图可沿用全局参数：保持原格式/转 JPEG/转 WebP；质量 1–100（仅适用于有损）；默认 `JPEG 80`、`WebP 80`（均为产品默认，不等同视觉质量绝对保证）；默认不改变宽高；可选最长边 2560 / 1920 / 1280 / 自定义。
- PNG“无损优化”独立模式，不显示质量滑块；压缩无收益时保留原图字节与类型，并明确标识。
- 可选批量顺序处理、逐文件进度状态（加载中/处理中/已完成/已跳过/失败/已取消）、失败重试、删除条目、全量清空。
- 压缩完成：原体积、输出体积、节省字节数/百分比、图片宽高、文件名、下载单张；成功项可一键 ZIP 下载。
- 通过轻量缩略图与前后对比交互实现视觉预览；预览不等于编码结果，必须使用实际 Blob 展示输出图。
- 区分“不支持的格式/损坏文件/超限/内存不足/浏览器能力不足/编码器载入失败/任务取消”。
- 中文、英文、日文页面，响应式 + 键盘可访问，静态 SEO 内容与 FAQ，隐私页。
- Cookie 不跟踪图片，默认无图片上传 API；无需登录；核心压缩完全离线可执行（首次下载静态资源后，离线缓存仅在后续有专门实现与验证时承诺）。

## 3. P1 延后范围

- AVIF 输出、输出编码策略自动选择、智能质量搜索、GIF 动图无损/有损压缩。
- SVG 优化、HEIC/HEIF 导入、文件夹批处理、PWA 离线支持、可选 EXIF/GPS 清理保证、颜色配置文件处理、批次持久化。
- 全部 P1 功能均不进入 v1 SEO 文案的“当前支持”列表；避免空工具页。

## 4. 不做事项

- 不做账户、云存储、历史图片列表、服务端处理、远端 URL 抓图、图片水印/AI 增强、付费 API。
- 不做误导性“任何图片压缩 90%”承诺；不做自动缩放并宣称无损。
- 不创建子域名之外的第二部署平台，不把主站源码引入本仓库。

## 5. 用户流程

1. 进入页面看到隐私说明“图片在此设备本地处理，不上传服务器”。
2. 用户拖拽 / 点击选择 → 本地校验格式、数量、体积、尺寸 → 渲染文件列表。
3. 选择格式/质量/最长边；PNG 无损模式隐藏质量；切换输出 JPEG 时展示透明背景会填白提示。
4. 点击压缩；任务队列单个处理（初版并发=1，可根据设备后续调优）。
5. 完成后显示“原始体积→新体积”、节省百分比；压缩更大也如实呈现，不能静默声称成功减少。
6. 下载单个输出文件，或选择成功文件压成 ZIP 下载；清空后释放内存。

## 6. 参数与边界规则

| 项目 | v1 默认/限制 | 说明 |
|---|---|---|
| 输入支持 | JPG/JPEG、PNG、WebP 静态图 | APNG/动画 WebP 暂拒绝或标注不支持；不能悄悄截第一帧当动画 |
| 批次数量 | 最多 20 文件 | 超限提示并拒绝多余项 |
| 文件体积 | 单张默认 30 MiB | 可配置；超限提示，不因扩展名绕过 |
| 图片像素 | 32 MP 桌面 / 16 MP 移动端初始保护值 | 这是保守工程值，按设备测试调整；严格防止解码炸内存 |
| 图片长边 | 默认不变；用户可设置上限 | 不自动放大图片 |
| 默认编码 | 原格式：JPEG 80/WebP 80；PNG OxiPNG 无损 | 原格式有损重新编码可能变大/失真 |
| 透明背景 | 输出 JPEG 时以白色填充 | 清晰提示；PNG/WebP 保留 alpha（如编码器支持） |
| PNG 同格式 | 原始二进制直接交给 OxiPNG | 不先用 Canvas 解码重绘；保护像素无损语义 |
| 输出反而更大 | PNG 无损模式返回原图 | 有损或尺寸变化模式保留输出并提示可改选原图 |
| 画质 | 1–100 slider，只应用于有损 JPEG/WebP | 数字是编码器质量参数，不是百分比画质 |
| 取消 | 立即终止活动 Worker 或重建专属 Worker | 取消异步计算不依赖编码器配合；保持后续可用 |
| 元信息 | v1 不提供 EXIF/GPS 必定删除或保留的保证 | 不得把“图片不上传”混同于“导出已清理元数据” |

> MiB 是 1024×1024 字节。UI 可展示 MB/MiB 其中一种，但需要一致。

## 7. 产品细节

- 状态：idle、validating、queued、processing、success、skipped、failed、cancelled。压缩中禁止更改当前任务参数；已入队任务采用点击启动时的配置快照。
- 体积比：`(originalBytes - outputBytes)/originalBytes * 100`，支持负值以标识体积增加，四舍五入展示。
- 已成功的单图需可重复下载；输出 Blob URL 仅在该项存在时保留。
- 图片压缩为 0%：真实展示“无明显体积改善”，不能显示虚构收益。
- ZIP 中同名文件做稳定去重（如 `photo.webp`, `photo-2.webp`），不得覆盖。
- 任务失败可单独重试，失败的条目不可打包 ZIP。
- 客户端处理时提示浏览器可能占用较高内存，建议避免过多超大图片。

## 8. 发布范围与完成定义

- P0 功能、三语言基础完整且经过审校；所有压缩流程均在网页本地完成，DevTools Network 中没有图片数据出站请求。
- 已在真实 Cloudflare Pages 的生产构建中验证 JPEG/PNG/WebP 的解码/编码/下载。
- 支持桌面和移动端，无明显主线程卡死；批量任务能够取消和释放内存。
- 文档、robots、sitemap、canonical、hreflang、隐私说明上线。
