# 261014-19-修复PNG半透明渐变投影被改图缺陷

## 任务背景
用户反馈在压缩带红色发光边框与半透明文字阴影的 PNG（“发起爽辣挑战”）时，压缩后原本平滑柔和的半透明霓虹渐变投影彻底丢失，变成了生硬刺眼的 100% 实心红色死边框，严重违反了“图片压缩不得篡改视觉语义（不改图）”的基本准则。

## 根本原因剖析
在 `lib/image/codec/quantize.ts` 色彩量化算法中存在两处严重缺陷：
1. **Alpha 通道粗暴二元化**：算法仅对 `a < 16` 的纯透明做了判断，而对于 `a >= 16` 的所有半透明渐变光晕（如 alpha 介于 20 到 200 的柔和投影），在映射输出时无脑硬编码赋值 `outputData[idx + 3] = 255`！
2. 这直接导致外围原本从透明到不透明、半透明衰减的发散光晕全部被强行写成了纯不透明实色，造成严重的“发光投影丢失、变成实心红边”视觉损毁。
3. 同时在全局策略上，未将“保持原格式”严格锚定在“纯无损通道”，导致原格式 PNG 默认误入了量化通道。

## 解决方案与技术改造
1. **严格 1:1 保留每个像素真实的 Alpha 透明度梯度**：
   - 彻底修复 `quantize.ts`：在色彩映射阶段，无论是否抖动，严格执行 `outputData[idx + 3] = data[idx + 3]`（保留原始像素的实际 Alpha 值）。
   - 对于完全透明（`alpha === 0`）像素置 0；对于半透明发光光晕（如 `alpha = 30, 85, 180`），RGB 匹配调色板代表色，Alpha 严格保留原值，柔和霓虹发光与投影效果 100% 完整重现，绝不产生硬边与实色破坏。
2. **策略彻底纠偏（恪守纯无损底线）**：
   - 更新 `lib/image/policy.ts` 中的 `shouldUseLosslessPngPath`：
     只要用户选择默认的 **【保持原格式】（Keep Original）**，PNG **100% 走纯无损优化通道（OxiPNG，直接优化 Deflate 字典，100% 原始像素与原始 Alpha 绝对不变，绝不改图）**！
   - 只有当用户显式选择转为 【PNG】且调低质量滑块时，才在严格保留 Alpha 的前提下做色彩量化。
3. **单测覆盖与门禁保障**：
   - 在 `tests/unit/quantize.test.ts` 中新增多梯度半透明光晕测试用例，断言量化后 Alpha 值必须与原图严格一致；
   - 全量 11 个测试文件 77 项单元测试全部绿灯通过，`yarn check` 四重门禁 0 错误通过。

## 三层验证
- **静态层**：`yarn typecheck` 0 错误。
- **运行时**：`tests/unit/quantize.test.ts` 新增半透明 Alpha 梯度断言通过，全量 77 项单元测试全绿。
- **系统级**：`yarn check` 四重门禁全绿通过。
