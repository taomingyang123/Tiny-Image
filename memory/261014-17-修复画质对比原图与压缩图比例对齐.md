# 261014-17-修复画质对比原图与压缩图比例对齐

## 任务背景
用户反馈在画质对比弹窗（`ImageCompareModal`）中，原图和压缩后的图不在同一个比例下显示，导致左右卷帘分割对比时画面严重错位（原图被异常放大，雪碧罐、文字和火锅盆左右错位，滑块把手在背景黑边区域空跑脱节）。

## 根本原因剖析
1. **DOM 盒模型不一致**：底层压缩图作为常规流中的 flex item，受外层容器高度约束自适应缩放；而顶层原图位于 `absolute inset-0 flex` 容器中，在没有统一具体宽高约束的情况下，`max-h-full` 在绝对定位 flex 容器中未按预期约束，导致原图以内在尺寸（750×1624）超大渲染，被裁剪并放大。
2. **滑块坐标系脱节**：之前滑块 `sliderPos`（0%~100%）是基于外层宽屏大弹窗（1024px 宽）计算的。当对比竖版长图时，图片仅占据中间部分宽度，滑块在左侧和右侧的大量区间内都在黑边空跑，导致视觉上把手在最右边而切分线却在图片中间偏左。

## 解决方案与技术改造
1. **引入统一锁定的 Image Stage 盒模型**：
   - 在弹窗可视区居中创建 `stageRef` 容器（`relative inline-block max-w-full max-h-full`）。
   - 由底层图片（`max-w-full max-h-[66vh] w-auto h-auto object-contain`）根据图片自然比例撑开舞台的真实渲染宽度与高度。
   - 顶层原图容器设为 `absolute inset-0`，原图使用 `absolute top-0 left-0 w-full h-full object-fill`，确保顶层原图与底层压缩图 100% 共享完全一致的 CSS 像素宽高。
   - 无论原图与压缩图原始像素尺寸是否缩放，两者在视口中以 100% 相同的对齐原点与长宽比渲染，像素级重合。
2. **重构滑块坐标系映射与手柄定位**：
   - 切分线与拖拽手柄移入 `stageRef` 内部定位，`left: ${sliderPos}%`。
   - `updateSlider` 以 `stageRef.getBoundingClientRect()` 为坐标基准，图片最左边缘精准对应 0%，最右边缘精准对应 100%，鼠标指针与分割线完全贴合。
3. **触控与快捷交互增强**：
   - 补充 `touchstart` 与移动端拖拽支持；
   - 支持双击舞台快速恢复 50% 居中；
   - 显式静态导入 `useI18n`。
4. **单测保障**：
   - 新增 `tests/unit/compare-modal.test.ts`，覆盖坐标系映射、键盘按键步进与节省率格式化。
