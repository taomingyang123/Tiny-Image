# 2026-10-14 · 性能调优与资源管理

## 任务背景与目标

对应任务 `T03-02`：排查内存泄漏风险、建立超限防御（大文件、超大像素、ZIP 容量溢出）、实现首屏零 WASM 懒加载架构并验证资源生命周期回收机制。

## 关键实现与改动

1. **首屏零 WASM 懒加载架构 (`lib/image/codec/`)**：
   - 严格遵循 AGENTS.md 约束 5，各格式编解码器（MozJPEG, OxiPNG, WebP）采用动态 `await import()` 按需载入。
   - 首屏访问时仅加载纯静态 UI/CSS/JS 主包，不发起任何 `.wasm` 二进制文件网络请求，仅在用户拖入图片并分发到 Worker 时才触发对应模块下载与实例化。
2. **三道超限防御与前置快速失败**：
   - **空文件与大文件拦截**：0 字节空文件直接阻断；单张超过 30MB (`DEFAULT_MAX_FILE_BYTES`) 立即拦截，绝不向 Worker Transfer 二进制浪费内存。
   - **超大像素 Canvas 保护**：桌面端 6400 万像素、移动端 2500 万像素前置拦截，防止 ImageData 申请巨额显存造成移动设备浏览器白屏崩溃。
   - **ZIP 归档安全容量保护**：归档总字节超过 100MB (`DEFAULT_MAX_ZIP_BYTES`) 拒绝客户端打包，保护主线程响应度。
3. **Blob URL 与 Worker 生命周期双向回收**：
   - 当任务被单个移除 (`removeTask`) 或全局清空 (`clearAll`) 时，严格执行 `URL.revokeObjectURL` 释放所有临时 `previewUrl` 和 `resultUrl`。
   - 队列 `destroy` 时不仅清理所有 ObjectURL，同时强制调用 `WorkerClient.terminate()` 终止 Worker 线程并清理超时定时器。
4. **自动化测试覆盖 (`tests/unit/performance-lifecycle.test.ts`)**：
   - 覆盖 5 项针对性测试用例，自动化断言空文件快速失败、30MB 超限拦截、100MB ZIP 保护、成对 ObjectURL 释放与 Worker 销毁。
