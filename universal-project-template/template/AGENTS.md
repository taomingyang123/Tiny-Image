## 执行纪律

### 任务与范围

修改代码、行为、数据或协作机制前登记 TASKS；已有任务置 doing，没有则按最大编号递增新建。纯问答及不影响行为的微小文案、格式调整可不登记。

同一项目 WIP=1：同时最多一个 doing。新需求与当前任务冲突时先登记 todo；用户明确要求立即切换时，原任务转 blocked 并记录做到哪、剩什么及插队编号。禁止顺手扩大范围。

状态：todo → doing → done，todo/doing → blocked，blocked → doing（仅当前没有 doing 时）。done 不回流；后续问题另建修复任务并引用原编号。

### 决策与断点

项目级结论写本文件，需求写 init.md，阶段及任务级结论写 TASKS。记录实际讨论过的被否方案及理由。每次收尾更新进展、证据与计数，即使任务未完成；待恢复项必须可直接接手。

### 三层完成定义

1. 静态：相关编译、类型、格式、语法或文档链接检查。
2. 运行时：受影响组件、命令、接口或服务实际运行，相关行为检查通过。
3. 系统级：真实代表场景端到端完成，输入、输出和持久化等符合任务行为。

按顺序验证。每层记录环境、命令或操作、结果和证据路径。未通过或无法运行时保持 doing 或 blocked。Mock 只能证明其覆盖范围，不替代真实集成验收。

N/A 仅用于确实不适用的层，并说明原因；无设备、没权限、服务不可达属于未验证。纯文档任务可将运行时/系统层标 N/A，但必须校验文档自身的结构与交付要求。

### 基线与授权

新项目首项为 F00 初始化运行基线；旧项目先核实现状，沿用原编号体系补建核验或修复任务，不重跑破坏性初始化。开始工作先检查运行契约，基线不足时优先补足受影响的能力。纯文档交付无需启动无关业务服务。

保存已有本地修改；不要为获得干净检查点而丢弃他人工作。提交、发布、迁移等动作按用户授权执行，不把模板当作自动执行依据。

## 日志与一致性

- TASKS 是任务状态的唯一事实源；MEMORY 是历史，ROADMAP.md 是阶段摘要。
- 每个登记任务 done 后立即写 memory 并更新索引。未完成但有重要决策或交接风险时也可记录，明确未验收状态。
- 未登记的微小文案、格式或行为不变的内部调整无需日志；功能、修复、重构、事故、选型与废弃能力需要记录。
- 文件名 `YYMMDD-HH-简述.md`；同天同功能追加 `## 补充（HH:mm）`，不重复新建。字段与四个章节见 docs/MEMORY-ENTRY-TEMPLATE.md。
- 长期坑点写 MEMORY 全局注意事项。只写可证实的事实，不补造测试、提交或历史日期。
- 阶段推进、当前位置变化或里程碑交付时更新看板；普通任务完成仅更新 TASKS 和 memory。
- 收尾报告实际产出、验证结果、限制与下一步，并给出文件路径。
