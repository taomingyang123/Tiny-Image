# 导入通用项目模板

## 目标与边界

把相邻 `template/` 中的文档应用到用户指定的项目根目录。整个流程仅初始化协作文档，业务开发、依赖安装和部署需依据用户后续任务进行。遵守目标仓库现有 AGENTS 与用户明确约定。

## 1. 选择模式

先确认目标目录；上下文已有明确目录时不重复询问。首次提问：

> 这是哪种项目？① 新项目（从零规划） ② 已有项目（盘点并接入现有规范）

用户已经明确模式则直接沿用。不要用文件数量判断新旧。空目录也可能是已有项目的新工作区；无法判断时等待用户选择，不执行依赖该答案的操作。

## 2. 只读盘点

读取目标 AGENTS.md、README.md、MEMORY.md、TASKS.md、init.md 和相关 docs。存在 Git 时查看状态，识别未提交修改。根据项目选读依赖清单、锁文件、构建配置、CI、目录和关键入口；没有 Git 时明确记为未建立版本基线。

不要读取或输出密钥值；环境配置只记录变量名和获取方式。读取文件前确认它属于目标项目，避免把模板自身误识别为业务代码。

区分三类内容：代码证实的现状、用户确认的未来方案、待核实的推断。文档和代码冲突时分别记录现状与意图，不能自动把其中一方改成另一方。

## 3. 分轮收集信息

每轮最多三个问题，已经提供或可靠提取的信息不再问。

新项目：
1. 项目名称、目标用户、要解决的问题。
2. 交付形态（网站 / 移动应用 / 小程序 / API / CLI / 库 / 数据项目 / 自定义）、首版必须完成的场景、明确不做的内容。
3. 语言框架偏好、数据存储需求、运行部署环境与重要约束。允许「无偏好」「暂不确定」「不需要数据库」。

用户无技术偏好时，根据需求提出 2–3 个候选方案，说明适用性、维护成本和限制，请用户选择。选择前不安装、不创建业务骨架；如需版本或平台能力等实时信息，再查官方资料。

已有项目：
1. 展示发现的名称、技术栈、目录和命令，请用户补充目标与当前阶段。
2. 询问本次期望：接入协作文档、继续现有任务、还是规划改造；迁移技术栈不能由导入模板自动触发。
3. 只对冲突和缺失的重要约束提问。缺少 init.md 时根据盘点生成草稿，不要求用户先手写一份。

## 4. 形成可审阅的导入草稿

在目标目录新建不重名的暂存目录（例如 `.template-import-draft-日期序号/`），生成文档草稿与文件变更清单。已有文件按章节合并，不全量覆盖。

- 新项目：把确认的项目资料填入模板；F00 保持 todo，初始化文档不代表运行基线完成。
- 已有项目：保留现有有效规则、阶段、编号、状态、证据、历史索引及 memory 文件。沿用原任务体系，编号从实际最大值递增；已有 F00 不重置。
- 存在 doing：保留并记录后续待办；用户明确要求插队时再把原任务置 blocked，写清断点。
- 仅用代码确认的功能可以写「已发现实现」，不能据此虚构 done 或测试通过。
- 模板与现有规则冲突时，在草稿列出差异、建议及理由，由用户裁定。
- AGENTS 的架构、路线与 TASKS 的阶段保持一致。未来阶段只写意图，进入前再细化任务。
- DATABASE 无适用数据存储时保留为「N/A：无持久化数据」或省略，并同步移除导航链接。
- 看板沿用目标项目已有格式；没有则使用 ROADMAP.md。看板不重复保存每条任务状态。
- 将两份 prompts 复制至目标 `docs/workflows/`，更新导入后 README 的使用入口；避免指向临时目录。

## 5. 落地文档

把草稿摘要和具体差异交给用户确认项目模式、架构和阶段。已有明确授权且内容没有新增决策时直接沿用，不重复确认。

确认后，落地前重新检查目标文件是否变化；若变化则重新合并。将将要修改的已有文档备份至不重名的备份目录，记录相对路径与恢复方式，再应用已确认的合并内容。不要删除旧 memory，也不要重编号、重置任务、修改业务代码或自动提交。

新建初始化或接入日志并加入 MEMORY 索引；同一天同一工作单元追加补充节。记录实际执行内容、确认来源、被否方案及理由；没有讨论过的方案写「无」，不要虚构。

## 6. 导入验收与交接

检查所有有效文档：
- 项目字段已替换；不确定项标明待确认，不把占位符当成实际命令。
- 相对链接可达，流程入口可用，没有来源项目标识或环境 ID。
- TASKS 五字段完整、编号唯一、doing 不超过一个、计数符合公式。
- 原有历史、任务状态、证据和业务文件完整保留。
- 架构/阶段/看板对应；运行契约没有未经实测的通过标记。

报告导入文件、关键选择、未决项与下一任务。文档落地与基线验证分开报告。新项目下一步是执行 F00；旧项目优先续接任务或执行新的基线盘点任务，不能宣布项目已可运行。

重复导入时只补差异，无实质变化则报告无变更，不重复创建任务或初始化日志。
