# 检查 memory 与任务一致性

默认只读；用户已要求补记或修复时，可以执行有证据支撑的修复，不需要再次询问同一授权。

## 收集

读取 AGENTS.md、TASKS.md、MEMORY.md、实际 memory 日志和已采用的看板文件。
有 Git 时查看最近 30 天的提交摘要及当前差异，按需读取相关补丁；无 Git 时继续检查文档一致性，并声明历史覆盖受限。不能只靠提交关键词判定改动性质。

## 检查

1. 任务编号唯一，行为/验证/状态/进展/证据齐全，doing 不超过一个。
2. done 的适用三层有证据；工具不可用不应标为 N/A。发现历史错误登记问题，不能虚构证据或直接将 done 改回 doing。
3. 每个已登记且 done 的任务有日志；重要的未完成决策也允许有日志。
4. 检查索引死链和孤儿日志。排除目录 README、日志模板和说明文件。
5. 日志字段 date/type/tasks/modules 与四节结构完整；旧格式先按等价字段理解，不强制重写历史。
6. 核对同天同功能疑似重复项，不仅凭日期认定重复。
7. 核对 TASKS 底部计数：总数 = 四种状态之和；分母 = doing + blocked + done；为零时比例 N/A。
8. 看板关联任务存在，阶段结论不高于实际验证状态，里程碑链接有效。
9. 对比实际代码差异与记录，标出疑似漏记的重要功能、修复、重构、决策等。无法证实的只列为待核实。

## 报告与修复

输出检查范围、通过项、问题列表（证据与建议）及未能检查的部分。
若仅请求检查，到报告即结束。若授权修复：修正可证实的计数和链接、补充事实充分的日志，保留旧记录与原时间信息；仅对缺失的实质信息提问。补记记录使用当前时间并注明所追溯事件日期，不冒充当时记录。
